# 多模态电商智能导购 Agent 项目定义文档 v0.1

**项目名称**：基于多模态 RAG 与约束推理的电商智能导购 Agent
**版本**：v0.1
**更新日期**：2026-08-01
**目标周期**：2–3 周

---

## 一、项目背景与目标

### 1.1 挑战赛题目

> 实现一个基于 RAG 的多模态电商智能导购 Agent，构建打通"意图理解—智能咨询—决策辅助"核心路径的电商 AI 导购系统，支持多模态输入与流式交互体验。

### 1.2 项目定位

本项目不仅是课程作业，更是一份可以写入简历、用于 AI Agent / AI 应用 / 算法工程实习投递的作品。因此必须满足：

- **完整可运行**：有闭环系统，不是 demo 脚本
- **技术深度**：不是简单调用大模型的聊天机器人
- **客观可评估**：有量化指标和对比实验
- **时间可控**：2–3 周内逐步完成
- **面试可讲**：需求分析、架构、RAG、检索、推荐、Agent 工作流、评估方法都能说清楚

### 1.3 核心目标

构建一个**以笔记本电脑为第一版实验品类**的智能导购 Agent，支持：
- 自然语言需求输入 + 商品图片/参数截图上传
- 意图识别 → 需求解析 → 约束提取 → 商品检索 → 排序推荐 → 对比分析 → 结果校验
- 流式输出带有证据依据的个性化购买建议

## 二、系统核心能力

### 2.1 为什么是 Agent，而不仅是 RAG 问答

| 能力 | 普通 RAG 问答 | 本系统（Agent） |
|------|-------------|----------------|
| 状态管理 | 无状态 | **维护用户需求状态，支持多轮更新** |
| 意图路由 | 单一检索 | **识别 purchase/compare/inquiry/multimodal 并路由** |
| 约束处理 | 隐式语义匹配 | **显式结构化硬约束过滤 + 软偏好排序** |
| 追问机制 | 无 | **信息不足时主动追问（澄清轮）** |
| 冲突处理 | 无法识别 | **无满足商品时解释冲突并引导决策（冲突解决轮）** |
| 工具调用 | 单一检索 | **多工具动态调用：解析→提取→过滤→检索→排序→校验** |
| 结果校验 | 直接输出 | **约束满足 + 参数准确 + 证据支持三重校验** |
| 多模态 | 仅文本 | **支持图片解析 → 参数提取 → SKU 匹配** |

### 2.2 核心流程

```
用户输入（文本/图片）
  → 意图识别与路由
    ├─ purchase → 约束提取 → 追问判断 → 硬约束过滤 → 软偏好排序 → 证据检索 → 推荐理由生成 → 校验 → 输出
    ├─ compare → 参数对齐 → 差异分析 → 校验 → 输出
    ├─ inquiry → 证据检索 → 单商品问答 → 校验 → 输出
    └─ multimodal → 图片解析 → 参数提取 → SKU 匹配 → 路由到上述分支
```

## 三、数据方案要点

详见 [`dataset_v0.2.md`](./dataset_v0.2.md)

### 3.1 数据规模
- **36–48 款具体 SKU**（非系列名称）
- **6–8 个主流品牌**
- **轻薄本 / 全能本 / 游戏本** 三种类型
- **4 个价位段**覆盖（3000–5000 / 5000–8000 / 8000–12000 / 12000+）

### 3.2 数据来源优先级
1. 品牌官方规格表（硬参数）
2. 电商商品详情页（价格、标题、截图）
3. 专业评测/用户评论（文本证据）

**每条 SKU 必须经过人工核验**，标注 `verification_status`。

### 3.3 文本证据分级
- **客观事实**（`fact`）：品牌官网参数，用于事实校验
- **有来源的证据**（`evidence`）：评测片段，用于 RAG 检索
- **派生总结**（`derived`）：人工/模型生成，**不作为事实校验标准答案**

### 3.4 多模态数据
- 每款 SKU：1 张主图 + 1 张参数页截图
- 用户上传截图 → 解析参数 → 匹配 SKU → 进入咨询/对比/推荐

## 四、Agent 设计要点

详见 [`agent_design_v0.3.md`](./agent_design_v0.3.md)

### 4.1 硬约束（13 个字段）
`budget_max/min`, `gpu_required`, `gpu_vram_min`, `ram_min`, `storage_min`, `weight_max`, `screen_size_range`, `resolution_min`, `refresh_rate_min`, `cpu_brand`, `category`, `required_ports`

**约束分类**：
- `explicit`：用户明确说（"预算8000以内"）
- `inferred`：系统推断（"写代码"→ 编程场景）
- `priority`：normal / critical / relaxable

### 4.2 软偏好（6 个维度）
`performance`, `portability`, `battery_life`, `value_for_money`, `brand`, `scenarios`

**权重机制**：三级制 `low/medium/high`，程序固定映射为数值，保证实验可复现。

### 4.3 场景化排序（5 个模板）
办公学习、编程开发/数据分析、AI/深度学习、游戏娱乐、视频剪辑/设计创作

每个场景有预定义的基础权重，叠加用户偏好调整。

### 4.4 追问机制
- **澄清轮**：信息不足时主动追问，最多 1 轮，每轮最多 2 个问题
- **冲突解决轮**：无满足商品时解释冲突并提供选项，**不计入**澄清轮次数

### 4.5 冲突处理
- 不直接推荐违规商品
- 分析冲突约束 + 提供放宽选项 + 展示 1–2 款最接近候选
- 最接近候选标注：满足哪些 / 违反哪些 / 违反幅度
- 违约成本计算：违反数量 > critical 约束 > 加权幅度 > 正常排序分数

### 4.6 工具设计（5 个外部工具）
1. `parse_product_image`：解析截图并匹配 SKU
2. `search_products`：结构化过滤 + 混合检索 + 排序（支持 normal/nearest 模式）
3. `retrieve_evidence`：获取事实与文本证据
4. `compare_products`：多商品参数对齐与差异分析
5. `verify_response`：约束满足 + 参数准确 + 证据支持三重校验

### 4.7 多样性控制
Top-5 中同一品牌最多 2 款（用户未限定品牌时）。

## 五、评估方案要点

详见 [`evaluation_v0.1.md`](./evaluation_v0.1.md)

### 5.1 P0 核心指标（必须完成）
| 指标 | 说明 | 计算方式 |
|------|------|----------|
| **CSR** | 硬约束满足率 | 全自动：推荐商品中满足全部约束的比例 |
| **Hit@5** | 候选召回命中率 | 全自动：Top-5 中命中允许集合的比例 |
| **PFA** | 参数事实准确率 | 半自动：规则提取参数 + 人工抽检 |
| **ESR** | 推荐理由证据支持率 | 半自动：论点与证据匹配 + 人工抽检 |

### 5.2 测试集
- **开发集**：20 条（prompt 调试、阈值调参）
- **正式测试集**：80 条（最终评估、消融实验）
- **覆盖 7 类查询**：正常购买 / 硬约束 / 多条件组合 / 模糊需求 / 冲突查询 / 商品对比 / 多模态

### 5.3 消融实验（4 个基线）
| 基线 | 说明 |
|------|------|
| **A：纯向量检索** | 仅语义相似度，无结构化约束 |
| **B：混合检索** | 向量 + BM25，无结构化约束 |
| **C：混合检索 + 结构化约束** | B + 硬约束过滤 + 软偏好排序 |
| **D：完整 Agent** | C + 意图识别 + 澄清机制 + 场景化排序 + 冲突处理 + 校验 |

### 5.4 工作量控制
- 标注：约 24 小时（两位标注者，100 条查询）
- 实验：约 1 周（含调试和统计检验）
- 总计：2–3 周内完成

## 七、技术亮点（面试可讲）

### 7.1 约束推理
- 不是简单关键词匹配，而是**结构化硬约束 + 语义软偏好 + 多维度融合排序**
- 约束有来源追溯（explicit/inferred）和优先级（normal/critical/relaxable）
- 冲突时**不违规推荐**，而是分析违约成本并引导用户决策

### 7.2 多模态 RAG
- 支持商品参数截图解析 → 提取参数 → 匹配 SKU
- RAG 检索语料分级（fact/evidence/derived），避免闭环自证
- 推荐理由有**证据支持**，不是大模型幻觉

### 7.3 Agent 工作流
- **状态驱动**：维护 UserNeedState，支持多轮更新
- **动态决策**：根据信息充足度决定是否追问，根据过滤结果决定是否进入冲突处理
- **工具调用**：5 个原子工具覆盖完整流程

### 7.4 可量化评估
- 4 个 P0 指标（CSR、Hit@5、PFA、ESR）可实际计算
- 4 个基线消融实验，验证每个模块的独立贡献
- 测试集 80 条，覆盖 7 类查询场景

### 7.5 工程实践
- 数据有核验流程，参数有事实校验，输出有证据支持
- 偏好权重三级制，保证实验可复现
- 违约成本分层排序，数值安全有上限保护
